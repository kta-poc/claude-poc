# 0003. チーム向けCLAUDE.md標準に共通骨格テンプレート+言語別記入例方式を採用

Date: 2026-07-03
Status: proposed

## Context and Problem Statement

60名規模のチーム(バックエンドGo、フロントエンドJS、GitLab、マルチレポ構成)へのClaude Code導入初期にあたり、各リポジトリのCLAUDE.mdの書き方を標準化したい。標準がないまま導入すると、リポジトリごとに品質がばらつき、便利さゆえに何でも書き込まれて肥大化し、守られない文書になるリスクが高い。テンプレートをどういう形式で提供するかの方式決定が必要である。

## Decision Drivers

- 導入初期の60人が「コピペして少し埋めるだけ」で始められる立ち上がりの速さ
- CLAUDE.mdは全セッションでコンテキストに読み込まれるため、肥大化はコスト増と指示追従の劣化に直結する
- 大原則「コードから導出できないことだけを書く」を構造で担保したい
- Go/JSの2スタックに対応しつつ、テンプレート自体のメンテコストは抑えたい
- まず1リポジトリでパイロットしてから横展開する段階的な導入計画

## Considered Options

- 共通骨格テンプレート1本のみ(言語非依存の見出し構成だけを配る)
- Go用・JS用の2本のテンプレート(コマンド・規約例を最初から焼き込む)
- 共通骨格1本+言語別記入例集を別添(骨格は1本に保ち、例だけ言語別に見せる)

## Decision Outcome

Chosen option: 「共通骨格1本+言語別記入例集を別添」。骨格の一貫性とメンテの容易さを保ちつつ、Go/JSそれぞれの完成イメージをコピペ可能な形で提供できるため。成果物は `docs/claude-md-guidelines/` に3点セット(template.md / examples.md / README.md)として配置した。

主な付随決定:

- テンプレートのセクション構成: プロジェクト概要/よく使うコマンド/非自明なコーディング規約/やってはいけないこと/アーキテクチャの要点(任意)
- 肥大化防止ガードレール(50行以内推奨・書かないものリスト・リンク原則・守られない指示は消す)はテンプレートではなく運用READMEに記載
- 組織共通ルールとして「日本語で会話」「秘密情報の禁止」「破壊的git操作の禁止」「パッケージ・ツールの無断インストール禁止」の4点のみをテンプレートに焼き込む。コミット規約・MR規約は既存の明文化がないため含めない
- 記述言語は日本語標準。ただしコマンド・ファイルパス・識別子は英語表記のまま書く
- 共通ルールの配布は当面コピー方式。まずGoバックエンドの1リポジトリでパイロットし、成功判定は参加者への定性ヒアリングのみ。乖離が実害になったら同期の仕組みを再検討

### Consequences

- Good: 骨格が1本なのでテンプレート改訂が1箇所で済み、リポジトリ間の構成が揃う
- Good: 記入例により導入初期のメンバーがほぼコピペで始められ、品質のばらつきを抑えられる
- Good: ガードレールを別添READMEに分離したことで、テンプレート自体が「書きすぎない」見本になる
- Bad: 記入品質は書き手依存の部分が残る(記入例から外れたリポジトリでは自力で埋める必要がある)
- Bad: 共通ルールのコピー方式は横展開後に乖離するため、いずれ同期戦略の再決定が必要

## Pros and Cons of the Options

### 共通骨格テンプレート1本のみ

- Good: メンテが最も楽で、言語が増えても対応不要
- Bad: 抽象的な骨格だけでは記入品質が書き手に大きく依存し、導入初期の立ち上がりが遅い

### Go用・JS用の2本のテンプレート

- Good: ほぼ完成品からのスタートで立ち上がりが最速
- Bad: 骨格の変更を2本に反映し続ける必要があり、乖離しやすい
- Bad: 例と規範が混ざり、「どこまでが標準でどこからが例か」が曖昧になる

### 共通骨格1本+言語別記入例集を別添

- Good: 骨格の一貫性(規範)と言語別の具体性(例)を分離でき、両立する
- Good: 記入例はコピペ元として使え、立ち上がりも速い
- Bad: ファイルが2つに分かれるため、読み手が例を参照しない可能性がある
